```text
OpenFrontier Method
├── ① 视觉前沿识别：从图像里提出“下一步可以去哪”
│   ├── FrontierNet 在关键帧上检测视觉前沿簇，预测探索信息增益 ĝᵢ
│   ├── 在 RGB 图像中标记各前沿；VLM 根据语言目标给出相关性 pᵢ
│   └── 语义加权：gᵢ = pᵢ × ĝᵢ
│
├── ② 三维定位与全局管理：决定“先去哪一个”
│   ├── 结合深度、相机内参与相机位姿，把二维前沿变成三维目标位姿
│   ├── 维护稀疏的全局前沿集合：合并重复项、清除已到达或无法到达项
│   ├── 距离加权：uᵢ = gᵢ / ‖pᵣ − pᵢ‖，选最高者作为下一导航子目标
│   └── 底层 PointGoal 策略或地图规划器负责执行；新观察到来后重新选择
│
└── ③ 目标发现与确认：决定“是否真的找到了”
    ├── 开放词汇分割检测疑似目标，用深度和相机位姿估计物体三维中心
    ├── 在物体前方插入高优先级的观察位姿前沿
    └── 到达后由 VLM 验证；确认则靠近物体，否则丢弃该假设
```

感觉主要贡献：

1. **视觉前沿是接口**：VLM 在同一张 RGB 图像中评价有标记的可行动位置，再把前沿定位到三维，连接语义推理与实际导航。
2. **探索与找目标结合**：FrontierNet 的 `ĝᵢ` 估计可能揭示的未知空间，VLM 的 `pᵢ` 估计该方向与目标的相关性；二者相乘，再除以机器人到前沿的距离。VLM 不直接输出每一步动作。
3. **稀疏全局记忆与模块化**：只维护少量三维前沿；前沿检测、VLM、目标验证和底层规划器可以分别替换。稠密三维语义地图不是语义决策的必需条件。

关键区别：

- `ĝᵢ` 是 FrontierNet 从图像与深度先验预测的**探索收益**；`pᵢ` 是 VLM 根据语言目标给出的**任务相关性**；`gᵢ` 是二者结合后的前沿价值；`uᵢ` 再计入到达距离。
- “无需训练／零样本”指**无需针对导航任务训练或微调这套系统**，不等于所有组件未经预训练：实验使用预训练的 FrontierNet、DD-PPO PointGoal 和通用 VLM。
- “不需要稠密三维语义地图”不等于完全不用几何信息：深度和相机位姿用于三维定位；可选轻量体积地图用于过滤障碍以及已探索完的前沿。

实验结果（SR / SPL，%）：HM3D Val **77.3 / 35.6**；MP3D Val **40.7 / 17.8**；OVON **Val Unseen 39.0 / 20.1**。同一套配置用于三个基准；更换 VLM 时，HM3D 成功率波动不超过约 3 个百分点。Spot 真实机器人实验共 10 次、成功率 70%，样本量较小。

局限：目标误判、步数耗尽和底层导航卡住是主要失败来源；检测到目标后，系统在停滞时缺少及时回到语义层重新推理的机制。附录还说明，部分“假阳性”来自基准真值未标注语义上符合目标的物体。

运行／评测配置：单张 RTX 4090（24GB）；无需任务训练，新增训练时长 0 小时。

### 实际准备机器时的含义

- **按论文配置运行：** 使用单张 RTX 4090（24GB）承载本地感知／导航组件，Gemini 通过 API 调用。24GB 是显卡总容量，论文未报告峰值显存，也未证明“20GB 显存就一定够用”。
- **CPU／内存：** 单环境评测可从 8–16 个 CPU 物理核心、32–64GB 内存、SSD 数据盘开始评估；这属于未实测的工程配置建议。增加并行评测环境或同时部署更多模型时，需要重新测量显存和内存。
- **若把 VLM 改为本地模型：** 需要额外存放视觉语言模型权重、视觉特征与推理缓存。官方代码支持本地 VLM，但不同模型大小、精度和并发数的显存差异很大；不能直接沿用 Gemini API 配置的显存预算。
- **若自行重训 FrontierNet、DD-PPO 或微调 VLM：** 这是额外研究工作，需按相应模型的原始论文、训练数据和步数另算；不能把它写成 OpenFrontier 原方案的必需训练成本。

### 训练时长与评测时长分开记录

**训练时长：0 小时。** 安装环境、下载已有权重与数据、运行仿真评测仍需要时间，不能把这些准备／运行时间计为训练时间。论文未给出完整基准评测的实际总小时数，因此这里不填写未经测量的固定值。

可先跑少量代表性 episode，记录平均用时，再估算：

```text
串行评测小时数 ≈ 评测 episode 数 × 平均每个 episode 用时（秒） / 3600
```

平均用时应包括仿真执行、感知模型推理、VLM 接口等待和场景切换。增加并发后，需要重新测量整体完成速度，因为 GPU 共享和 API 限流会影响吞吐量；不能直接按并发数做线性加速。
