# Uni-NaVid Method

```text
Uni-NaVid Method
├── ① 统一视频与任务接口：怎样用一个模型完成不同导航任务？
│   ├── 视觉：第一人称单视角 RGB 视频 → 冻结 EVA-CLIP → 每帧 256 个 patch tokens
│   ├── 语言：路线指令、物体目标、人物描述或问题 → Vicuna tokenizer → 语言 tokens
│   └── 模态对齐：压缩视觉 tokens → 两层 MLP → 与任务标记、指令共同输入 Vicuna-7B
│
├── ② 在线分级记忆：怎样保留导航历史并降低视频处理成本？
│   ├── 当前观测：8×8 网格 → 64 tokens，保留眼前场景的较细空间信息
│   ├── 短期记忆：最近 B=64 帧，每帧 2×2 网格 → 4 tokens
│   └── 长期记忆：更早每帧先压成 1 token → 与末尾长期 token 比较 → 相似则加权合并
│
├── ③ 多步动作与问答生成：怎样从环境理解进入导航闭环？
│   ├── 导航模式：加入 <NAV> → 自回归预测未来 4 个前进／左转／右转／停止动作
│   ├── 问答模式：不加入 <NAV> → 根据视频与问题生成答案；EQA 先导航、停止后再回答
│   └── 异步部署：执行待完成动作时上传新观测 → 生成更新动作 → 支持非阻塞导航
│
└── ④ 多任务监督训练：怎样让语言模型学会移动并保持视频理解？
    ├── 参数分工：冻结视觉编码器 → 训练 MLP 投影器与 Vicuna-7B；池化及相似度合并无可学习参数
    ├── 正文训练：先训练投影器进行模态对齐 → 再联合微调投影器与 LLM
    └── 数据与监督：约 3.6M 导航样本 + 2.3M 视频理解样本 → 监督动作序列或文字答案
```

**主要贡献：**围绕 EVA-CLIP 与 Vicuna-7B 构建视频导航 VLA，统一视觉语言导航（VLN）、目标物体导航（ObjectNav）、具身问答（EQA）与语言描述的人物跟随。其主要研究贡献是将不同任务转换成共享的视频、语言、动作接口，用多任务数据验证统一模型的能力与任务间收益；主要结构设计是在线视觉 token 合并，通过当前、短期、长期三级表示及历史特征复用降低视频推理成本，结合未来四步动作预测支持异步导航。数据方面，论文整理约 3.6M 导航样本，并构建具有语言人物描述和干扰人物的跟随基准。EVA-CLIP、Vicuna、网格池化和相似度合并均有已有技术基础，贡献应落在这些部件的导航化设计、统一训练和实验验证上。依据见 §I、§III–V、Figs. 1–4。

**输入：**自然语言任务，以及截至当前时刻的第一人称、单视角 RGB 视频。策略模型不需要深度图、里程计、预建拓扑图或显式三维语义地图作为输入；ObjectNav 将目标类别写成搜索指令，人物跟随将外观描述写成跟随指令。EVA-CLIP 对每帧产生 256 个 patch tokens，随后进行空间池化。Fig. 2 图注中的“每帧 64 tokens”对应当前观测经池化后的表示，§IV-A 中的 256 对应池化前的 patch 数，两者属于不同处理环节。网格表示特征的空间划分，不能理解为将原始图像缩成 8×8 或 2×2 像素。实机底层控制另有传感器使用，见后文部署说明。依据见 §III、§IV-A–B、Fig. 2。

**历史：**设当前时刻为 `T`，短期缓冲长度 `B=64`。当前帧 `x_T` 保留 64 个 tokens；`x_(T−B)` 至 `x_(T−1)` 共 B 帧，每帧保留 4 个 tokens；更早的帧每帧先压缩为 1 个 token，再依据时间相邻的视觉相似度合并。长期记忆最终保留 M 个 tokens，其中一个 token 可以代表多帧历史。忽略分隔符和语言，历史足够长时输入视觉 token 数约为 `64 + 4B + M = 320 + M`。M 由场景变化和合并结果决定，论文没有为长期记忆规定固定容量，因此不能把该设计解释为总上下文长度恒定。三级记忆保存的是视觉特征；模型通过这些特征理解环境经历，文中未维护可直接查询坐标的显式占据地图。依据见 §IV-B、式 (2)–(6)、Algorithm 1。

**在线更新与合并：**收到新帧后，原当前观测从 64 个 tokens 压缩成 4 个，进入短期记忆；短期缓冲中最旧的一帧从 4 个 tokens 压缩成 1 个，进入长期记忆。论文只对跨越分组边界的特征继续池化，并复用此前计算，避免每次重新编码全部历史图像。新长期 token `z` 与末尾长期 token `h` 的余弦相似度超过阈值时，更新为 `h ← (K×h + z)/(K+1)`，并将代表的帧数 K 加一；否则追加新 token。论文设置 `τ=0.95`。这是按时间相邻关系进行的局部合并，未实现对全部历史的全局检索，也没有根据当前指令选择重要历史帧。网格池化、余弦比较和上述加权平均本身没有需要梯度更新的网络参数。依据见 §IV-B、式 (3)–(6)、Algorithm 1。

**任务统一与问答切换：**视觉 tokens 经两层 MLP 投影到语言模型的表示空间，按长期、短期、当前观测的次序，与导航标记 `<NAV>` 和任务文本共同输入 Vicuna-7B。加入标记时生成动作，不加入时生成文字。EQA 在导航阶段使用问题作为任务条件，模型先移动寻找有关物体；发出停止后，移除导航标记，再依据导航历史回答。该机制使“为回答问题而移动”和“直接回答”具有明确的输出模式。模型的物体识别、指令进度判断及动作选择由共享网络完成，标准结构没有独立的目标检测器、停止分类器或 frontier 规划器。依据见 §IV-C、§VI-A、Fig. 2。

**论文与公开代码的区别：**截至 2026-10-16 核对的官方 `main` 分支，`uninavid_arch.py` 中 `online_process_tensor()` 与 `process_tensor()` 的默认短期长度为 64，相似度阈值为 **0.985**，与论文的 **0.95** 不同。`compress_type='grid:2'` 对应每帧 4 个历史 tokens，当前帧单独生成 64 个 tokens。实现先做网格池化和 MLP 投影，再在投影后的历史特征上合并；论文流程则先合并再投影。MLP 含非线性时，两个计算顺序通常不等价，因此应分别描述论文与代码。

公开离线入口在任务开始时调用 `initialize_online_inference_nav_feat_cache()`，每次推理只编码新收到的图像，并利用模型内部视觉缓存保留历史。`feat_cache` 通过拼接继续增长，`online_process_tensor()` 虽只选取最近 64 帧作为短期输入，却没有在该路径裁掉缓存中的旧特征，因而“送入 LLM 的 tokens 减少”不代表整个程序的视觉缓存恒定。`generate(use_cache=True)` 用于生成过程，入口没有显式把上一导航步的语言模型 `past_key_values` 传入下一步；可以确认的跨步复用是视觉特征缓存。代码使用 `[Navigation]` 作为对应的特殊标记字符串，论文用 `<NAV>` 表述。上述为代码静态核对，未运行官方模型进行数值复现。[模型与记忆实现](https://github.com/jzhzhang/Uni-NaVid/blob/main/uninavid/model/uninavid_arch.py)、[离线入口](https://github.com/jzhzhang/Uni-NaVid/blob/main/offline_eval_uninavid.py)。

**输出：**

- 导航模型：一次自回归生成未来 4 个基本动作，动作集合为 `FORWARD`、`TURN-LEFT`、`TURN-RIGHT`、`STOP`。四步预测表示生成一个动作序列，序列内各动作仍按自回归方式预测。
- 模拟执行：论文定义每次前进 25 cm，左右转向 30°。移动发生于连续环境，但输出仍是离散的低层动作。基准执行预测序列，并在首个预测动作是停止时触发停止；策略自身没有输出连续航点或电机力矩。
- 具身问答：导航结束后移除导航标记，生成物体颜色、所在房间等问题的文字答案。
- 实机执行：模型在服务器生成动作，机器人通过本地运动规划与控制接口执行；运行中继续上传新图像并更新后续动作。
- 公开离线示例：生成小写 `forward/left/right/stop`，并将 `forward` 转成 0.5 m 用于轨迹表示／可视化，区别于论文的 0.25 m 训练与基准动作。该示例读取预录视频，不能单独验证机器人闭环执行效果。依据见 §III、§IV-C、§VI-A 及上述离线入口。

**训练数据：**论文正文统计约 **3.6M 导航样本，来自约 80K 条轨迹**，覆盖 861 个仿真场景。VLN 使用 R2R-CE 与 RxR-CE，约 2.4M 样本；ObjectNav 使用 HM3D，约 483K；EQA 使用 MP3D-EQA，包含约 240K 视频动作样本及 10K 视频答案样本；人物跟随在扩展的 Habitat 3.0 环境中采集约 544K 样本。各任务数值经过取整，不能强行要求显示的小计与 3.6M 完全一致。导航样本统一为“截至时刻 T 的视频、任务文本、未来四个专家动作”，同一条轨迹可产生多个训练样本。物体导航训练目标来自预定义类别集合；HM3D-OVON 用于检验开放词汇迁移，不能据此理解为直接使用全部 OVON 目标类别进行导航训练。另加入约 2.3M 视频理解样本，包含视频问答与描述，使总数据约为 5.9M。依据见 §V-A–B、Fig. 3。

**主要训练什么：**视觉编码器 EVA-CLIP 使用预训练权重并冻结；两层 MLP 学习将视觉表示映射到 LLM 的输入空间；Vicuna-7B 学习结合视频历史与语言条件预测动作或答案。池化尺寸、短期缓冲长度和相似度阈值属于设定的结构与超参数。导航训练属于专家动作监督下的模仿学习，问答训练采用答案文本监督；该训练路线未报告 PPO／GRPO 等奖励优化阶段。公开代码对提示词和视觉位置使用 `IGNORE_INDEX`，监督模型应输出的部分。自回归目标可写为 `L = −Σ_i log p_θ(y_i | V, I, y_<i)`：V 是压缩视觉历史，I 是指令或问题，y 是专家动作字符串或参考答案。一个动作名称可能对应多个 tokenizer tokens，因此“四个动作”与“恰好四个底层词表 tokens”需要区分。[训练代码](https://github.com/jzhzhang/Uni-NaVid/blob/main/uninavid/train/train.py)。

**训练阶段与披露差异：**本地正文 §V-B 将训练描述为两阶段：第一阶段只训练投影器，使用与 LLaMA-VID 相同的模态对齐数据；第二阶段联合微调投影器和 LLM，使用 2.3M 视频理解样本及 3.6M 导航样本。导航样本带 `<NAV>`，视频问答样本不带该标记。应理解为先建立视觉语言接口，再通过联合监督学习导航和问答。

作为补充来源，arXiv v2 的 §X-C 则把“图像问答对齐、视频问答微调”归入第一阶段，再将导航训练归入第二阶段，与正文分期不同；它也没有在该段完整重述正文的混合数据计划。该补充材料报告 VLN 使用 DAgger 补充专家标签，ObjectNav 收集 L3MVN 成功搜索轨迹。这里记录来源差异，具体复现仍需核对实际数据与阶段配置。[arXiv 补充说明 §X-C–XI-A](https://arxiv.org/html/2412.06224v2#S10.SS3)。

公开 `uninavid_stage_1.sh` 从 Vicuna-7B 加载，`uninavid_stage_2.sh` 从 Uni-NaVid 权重加载；README 将其分别说明为从 Vicuna 训练和基于 Uni-NaVid 继续微调的入口。两者均指向发布的 500 条样本子集，不能仅凭脚本名称将其直接对应成论文完整的“投影器对齐／联合微调”两阶段。两脚本均设置 `tune_vision_encoder=False`、`mlp2x_gelu`、1 FPS、BF16、1 epoch、每设备 batch size=8、梯度累积 2、学习率 1×10⁻⁵、warmup ratio=0.03、余弦学习率、最大序列长度 2048，以及梯度检查点与 DeepSpeed ZeRO-2。这些属于公开示例参数；运行设备数依部署决定，不能据此推出论文正式全局 batch size。[第一份训练脚本](https://github.com/jzhzhang/Uni-NaVid/blob/main/scripts/uninavid_stage_1.sh)、[第二份训练脚本](https://github.com/jzhzhang/Uni-NaVid/blob/main/scripts/uninavid_stage_2.sh)。

**训练算力与推理部署：**本地正文 §V-B 报告使用 **40 张 NVIDIA H800，约 35 小时，共约 1400 H800 GPU·小时**；训练视频按 1 FPS 采样，训练 1 epoch。该数值是作者报告的训练用量，不包含基座模型原始预训练，也不能当作数据采集、所有调参和消融实验的项目总成本。正文没有拆分每阶段的 GPU 时长，也未给出最低显存、最少设备数或完整数据混合比例。

论文 §VI-A 使用远程 **NVIDIA A100** 进行实机推理，报告约 **0.2 秒生成未来四步动作**，对应约 5 Hz 的模型推理频率；机器人执行期间异步上传新图像。补充材料说明载体为 Unitree Go2，策略只读取 RGB，机载 LiDAR 服务于本地运动控制，并另外报告约 0.3 秒通信时间。因此，5 Hz 应限定为报告的模型推理速度，不能直接等同于含网络、控制及动作完成时间的整机闭环频率。[实机补充说明 §XII](https://arxiv.org/html/2412.06224v2#S12)。

**消融与配置说明：**Table X 的 VLN 列为 RxR 结果，与 Table III 的 48.7% 对应。仅当前观测、当前加短期、当前加短期与长期三种配置的 VLN SR 依次为 **9.61%、39.7%、48.7%**；ObjectNav SR 为 **44.3%、67.8%、73.7%**；EQA ACC 为 **32.5%、44.1%、47.3%**；跟随 SR 为 **56.3%、59.7%、61.2%**。这些结果支持视觉历史对导航有帮助，VLN 尤其依赖历史，而跟随在该基准中更依赖近期观测。它们并未直接比较所有其他记忆压缩方法，也不能证明任意场景下越久远的历史越重要。

同表去掉导航标记时，VLN SR 为 35.2%、ObjectNav SR 为 69.1%、EQA ACC 为 20.4%、跟随 SR 为 55.1%；去掉 VQA 数据时依次为 40.5%、50.6%、1.19%、58.8%。该结果支持任务标记和视频理解数据的作用，EQA 的下降尤其明显。Fig. 8 展示多任务相对单任务训练的收益，以及增加数据规模后的性能变化；正文也指出收益随数据扩大而趋缓。图中的数据规模与导航样本统计属于不同展示口径，阅读时应核对是否包含辅助视频数据，不能将接近 6M 的总训练样本都称作导航样本。依据见 §VI-D、Fig. 8、Table X。

**局限与复现边界：**作者在 §VII 指出，目前只覆盖四种已定义任务，对机器人尺寸采用相对标准的配置，并且输出仅为短期离散动作序列；扩展到更多任务、不同机器人尺寸及更平滑的连续轨迹仍有空间。就记忆设计而言，远期每帧压成一个 token 会丢失细粒度空间信息，相似度合并也没有显式保证保留任务所需的小物体细节，这是结构上的信息保留风险，不能直接当作论文已经单独验证的失败原因。长期 token 数没有硬上限，公开实现的中间特征缓存也会增长，因此尚不能把它概括成任意长任务下固定内存、固定延迟的系统。
