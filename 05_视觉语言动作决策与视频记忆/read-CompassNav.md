# CompassNav Method

```text
CompassNav Method
├── ① 候选动作构建：怎样把导航变成 VLM 能回答的视觉选择题？
│   ├── APM：根据当前深度图生成可通行方向，以极坐标 (r, θ) 表示候选移动
│   ├── 探索筛选：累积深度与位姿构建二维探索图 → 优先保留通向未探索区域的动作，再补充已探索方向
│   └── 视觉标注：按角度间隔去除过密候选、限制移动距离 → 将动作画成带编号的箭头叠加到当前 RGB 图像
│
├── ② 两阶段模型微调：怎样从模仿单个动作转向比较多个动作？
│   ├── SFT 初始化：Qwen-QvQ 成功导航示范 → 用“分析文本 + 动作编号”监督微调 Qwen2.5-VL-7B
│   ├── RFT 数据：用仿真器全局信息和 A* 为每个候选落点标注到目标的测地距离，并回溯采集其他可行路线
│   └── GRPO 优化：同一观察采样多个回答 → 连续距离评分 + 差距感知最优动作奖励 → 改进动作选择策略
│
└── ③ 导航闭环与停止：怎样把模型的选择变成实际运动？
    ├── 模型决策：输入目标与带箭头的当前观察 → 输出 <think>...</think><answer>k</answer>，限制 k 为有效候选编号
    ├── 动作执行：将编号映射回 (r, θ) → 先按 30° 转向，再按 0.25 m 步长前进 → 获取下一帧观察
    └── 停止判断：独立的、未微调的 Qwen2.5-VL-7B Stop Agent 根据视觉判断目标是否到达 → 决定停止或继续
```

**主要贡献：**围绕 Qwen2.5-VL-7B-Instruct 构建 SFT（监督微调）再 RFT（强化微调）的导航训练方法。关键在于 Compass-Data-22k 的全候选动作距离标注，以及 Gap-Aware Hybrid Reward（差距感知混合奖励）：训练反馈覆盖各个候选动作的相对质量，优劣明显时强化最优动作，多个动作接近时给予接近的评分。作者将这种训练目标概括为从 Path Imitation 转向 Decision Understanding；从实现上看，核心是已有多模态模型的任务微调，并配合候选动作生成、低层控制与停止判断。

**输入：**目标指令，以及叠加了候选动作箭头的当前 RGB 观察。ObjectNav 的目标是文字指定的物体类别；Instance Image-Goal Navigation（IIN）的目标由参考图像指定。系统还使用深度图和位姿构建可通行区域、探索状态与候选动作；这些几何信息通过 APM 影响提供给 VLM 的候选集合。训练标注使用目标的全局坐标计算 A* 距离，推理时不向策略提供这一目标坐标或距离向量。

**历史：**核心 VLM 的训练输入不拼接历史图像或历史文本摘要，作者称为 memory-agnostic training。系统层面，APM 仍累积深度和位姿构建二维探索图，将已观测到的 2 m 邻域标记为已探索，以减少重复移动。因此，应区分“VLM 不直接接收历史帧”和“导航系统保留几何探索状态”。Table 13 的历史输入消融使用 Qwen2.5-VL-7B 基座：无历史、文本历史、图像历史的 SR 分别为 45.3%、45.0%、34.7%；这些数值对应所测试的输入方案，不能据此推断所有记忆方法均无效。

**输出：**

- 导航 VLM：生成分析文本和 `<answer>k</answer>` 动作编号；masked multiple-choice decoding 将最终动作限制在有效候选集合中，ObjectNav 提示还允许编号 0 表示掉头。
- 导航层：将所选候选 `(r, θ)` 转成确定性的“先转后走”序列；θ 先由弧度转换成度，再按 `ceil(|θ| / 30°)` 计算转向次数，前进次数按 `ceil(r / 0.25 m)` 计算。
- Stop Agent：每步单独检查是否已接近并正确看到目标，输出 1 表示停止、0 表示继续；它与负责选择移动方向的微调模型分开。

**训练：**数据在 Habitat-Sim 的 HM3Dv2 训练场景中构建，分为 SFT 与 RFT 两部分。SFT 保留 Qwen-QvQ 成功导航时的分析与动作，对整段教师输出计算交叉熵损失；使用 LLaMA-Factory 和 LoRA，rank 为 64、alpha 为 128、dropout 为 0.05，应用于注意力投影和前馈投影层。最大序列长度为 4096，训练 3 epochs，全局 batch size 为 128，学习率为 2×10⁻⁴，采用 AdamW、余弦调度、0.03 warmup ratio、BF16、DeepSpeed ZeRO-2 和梯度检查点。RFT 使用 EasyR1 与 GRPO，由 SFT 的 LoRA 权重初始化 actor，并保留冻结参考策略；学习率为 1×10⁻⁶，KL 系数为 0.01，策略更新 batch size 为 128、每设备 micro-batch 为 4。每个输入采样 5 个回答，训练采样 temperature 为 1.0、top-p 为 0.99，rollout batch size 为 512；评估时采样 1 个回答、temperature 为 0.5。论文未另列 RFT 阶段各层的可训练参数范围。

**奖励与数据生成：**RFT 样本保存最优动作编号及全部候选的 A* 距离向量。基础分为 `s = softmax(-d / τ)`；确定性系数为 `g = clip((d_second - d_best) / (|d_best| + ε), 0, 1)`；最终奖励为 `clip(s_i + B × g × 1[i 为最优动作], 0, 1)`，采用 τ=0.5、B=1.0。最优与次优差距较大时，最优动作获得更强额外奖励；差距很小时，保留接近的连续评分。生成训练数据时，若候选距离接近或确定性低于 0.1，就记录该状态，待当前任务结束后回溯执行其他选择。GRPO 的核心导航奖励根据回答中选中的动作计算，分析文本通过序列级奖励间接优化；距离向量用于计算奖励，不要求模型直接输出距离，也未逐句验证其分析是否正确。

**训练算力与推理部署（论文配置）：**SFT 使用 8 张 A800，约 12 小时；RFT 使用 8 张 H200，约 170 步，每步约 20 分钟。由此估算，单次 RFT 约 56 小时 40 分钟，对应约 453 H200 GPU·小时；SFT 对应约 96 A800 GPU·小时。两种硬件的 GPU·小时不能直接视为等价算力，上述数字也不包括数据生成和全部消融实验。实体部署采用 ROSMASTER X3、Orbbec Astra Pro RGB-D 相机、本地中继计算机与局域网内的单张 H200 服务器。论文未单独报告完整推理链路的逐步时延、峰值显存或最低硬件要求。

**评测：**主要任务为 ObjectNav 与 IIN，在 HM3Dv1-val、HM3Dv2-val、MP3D-val 等未见场景上评估 SR 与 SPL；附录 B 将成功定义为在最多 500 步内执行停止，且距离目标不超过 1 m。Table 1 的 HM3D、MP3D 结果分别为 SR/SPL=56.6%/27.6%、42.0%/17.5%。Table 2 中，ObjNav 的基座、SFT、SFT+RFT 结果依次为 45.3%/17.5%、54.1%/23.1%、61.6%/27.8%；最终 IIN 为 35.6%/14.8%。HM3D-OVON 已在附录 Table 6 评测，采用与 Nav-R1 相同的 Val-Unseen 设置：CompassNav 为 43.5%/21.6%，Nav-R1 为 42.2%/20.1%；该表未报告 Seen 与 Seen-Synonyms 两个划分。附录还报告 ProcTHOR 上 58.1%/32.8%；实体机器人部分提供定性轨迹示例，未列出系统性的真机 SR/SPL 表。

**消融与配置说明：**Table 4 中，直接从基座进行 RFT 的 SR 为 23.5%，从 SFT 初始化再做 RFT 为 35.6%；Table 5 中，Binary、Min-Max、Gap-Aware 奖励的 SR 分别为 29.5%、29.2%、35.6%。Table 3 的 NavNuances 评测覆盖方向、计数、地标、区域及垂直移动等能力，垂直移动得分由基座的 7.88 提升至 22.94，支持相应行为能力改善；“生成分析文本”本身不等于已验证分析的忠实性。原文有几处口径需要保留：Fig. 3 将两个子集分别标为 11k，但附录 C.2 写初始 54k 轨迹过滤后约 10k；Table 2 的 SFT IIN SR 为 23.9%，Table 4 的 SFT (Full) 为 23.3%，文中未解释这一差异。Tables 1–2 的 HM3D 相关数字也不同，表头未完整标明 v1/v2 对应关系，以上按各表原标签分别记录。正文将 HM3D-OVON 比较指向 Fig. 6，但实际数值位于附录 Table 6，Fig. 6 展示奖励差距与训练曲线。
